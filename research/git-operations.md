# Git 与 GitHub 操作指令

研究 Skill 负责提出操作目标，Git 工作流交给当前环境中已安装的 GD 指令或 GitHub 插件。
不要猜测 GD 的命令名、参数或安装路径；使用前读取环境实际提供的指令说明。
GitHub 插件按运行时暴露的工具执行，不能假设它支持本地暂存、提交或工作区管理。

## 工作区与变更

向可用的 GD 指令交付以下任务目标：

- 检查当前分支、远端、未提交变更及仓库约定，识别本次研究的文件范围。
- 需要隔离变更时建立或复用合适的工作分支，遵守受保护 main 的要求。
- 检查档案、观察批次、证据和报告的文件差异，排除无关文件、凭据及临时计划。
- 用户授权提交时，仅提交本次范围；授权推送或更新 PR 时，继续完成对应步骤。

如果环境没有提供可用 GD 入口，不编造调用方式。可以使用已授权且可用的 Git 工具完成
相同目标；缺少能力时明确说明具体缺口，仍继续不依赖该操作的数据研究。
不因采用这些指令而额外增加确认流程；授权范围沿用用户当前请求与已有约定。

## GitHub 来源采集

优先使用 GitHub 插件读取仓库元数据、提交、固定版本文件、发布记录和提交差异。
根据实际工具能力组织调用，保存来源 URL、仓库数字 ID、提交／版本、采集时间及原始内容。
完整性要求不会因更换工具而降低：仍需处理分页、截断、访问失败和默认分支与发布包的区别。

插件未提供某类数据时，使用其他可用的只读方式补充，或记录缺失边界。
`scripts/capture_github.py` 是基于已认证 `gh` 的可选采集实现，不是两个 Skill 的必需依赖。
通过插件获取等价证据后，按共享数据模型准备观察批次，后续计划、应用与校验流程相同。

## PR 与检查

用户授权创建或更新 PR 时，使用可用 GD 指令或 GitHub 插件执行，并保留返回的 PR 链接。
说明最终行为、数据范围、验证结果及未覆盖边界。检查 GitHub Actions 的实际结果，
不能将本地校验通过写成远端 CI 通过。更新已有 PR 时复用它，避免重复创建。
本仓库 `main` 要求 `Repository checks` 通过；不得绕过保护，也不得从提交／推送授权推断合并授权。
