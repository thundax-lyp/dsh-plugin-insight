# dsh-project-memory：把恢复上下文做轻，而非把记忆量做大

核查对象：`00080000/dsh-project-memory`，提交 `fe7ac6cab91784a34996aede007d3586f0ff2def`，源码和公开 npm latest 均为 0.6.2。

## 采用短评

- **用途：**在项目内保留任务、文件关联、文档／符号索引和经验，帮助新会话恢复工作。
- **亮点：**默认读到再索引，召回附来源；确定性索引不用模型调用，能从较小范围试起。
- **关键质疑：**多保存、多召回是否真的减少恢复时间与错误？目录所说“零成本”没有覆盖默认嵌入表、提示占用、噪声治理和跨作用域经验维护。
- **建议：**本轮优先试用候选：同一项目经常换会话、已有明确任务验收的人，可先做单项目对照；尚不能作为安装推荐。

## 场景、替代办法与合格标准

任务是隔几天或换会话后，继续未完成的开发工作。输入是文件、任务步骤和人工／Agent 保存的经验；合格结果是能找回正确决策、恢复任务且避免引用过时材料。

最便宜的基线是 AGENTS／交接文档、任务清单加 rg，而不是另一套更复杂的记忆系统。高频换会话、大量重复梳理的人可能有价值；一次性小项目未必值得增加一套持久化状态。

## 用户操作、后台处理与异常

用户安装、确认项目根、按需要选择任务；会话事件将 todo 与文件操作关联到项目任务。后台按读取触发索引，watch 刷新显式监控的根；检索返回来源，用户或 Agent 回查原文。恢复会话使用 list_tasks／select_task，避免重新描述全部背景。

事件接口不可用时，作者文档称任务工具退化为普通记录；子 Agent 不自动创建任务。因此“跨会话任务恢复”不能外推到所有宿主和委派路径。需要确认是否漏同步，而非仅看工具注册成功。

经验有 task／project／global 层级，跨任务积累可触发提升；全局层在召回中可见。它便利复用，也要求检查项目专属经验是否被过度泛化。[作用域与提升](https://github.com/00080000/dsh-project-memory/blob/fe7ac6cab91784a34996aede007d3586f0ff2def/src/insight-store.js)提供机制证据，不能据此宣称已发生数据泄漏。

forget 可以按 ID 或关键词删除，无撤销，匹配过多时拒绝执行；真实试用先备份、用精确 ID 验证删除边界。[删除工具](https://github.com/00080000/dsh-project-memory/blob/fe7ac6cab91784a34996aede007d3586f0ff2def/src/tools/forget.js)说明的是功能边界，本轮未执行删除。

## 成本与关键洞察

确定性索引不额外调用 LLM，是可辨识的成本优势；但宿主 Agent 仍要消费召回内容。autoContext 默认启用，maxTokens 400 的预算在源码中转换为字符预算，不能视为精确账单上限。
首次是下载、项目根／任务绑定与索引准备；持续是索引 CPU／内存／磁盘、模型阅读提示、噪声复核与索引维护；开启扩展／反思再加模型费用；迁移还要保留和校验本地／global 状态。没有实测，现金及人工时间未知，“零操作成本”不成立为本轮已验证结论。

**判断：**值得验证的是能否减少“重新定位和纠正旧认识”的时间，而不是多存了多少条记忆。来源引用、读时索引和默认关闭辅助模型调用支持低范围试验；反例是项目很小、交接文档已足够，或错误经验长期被召回。作者展示的索引规模和合成 P/R 不是本轮端到端增效证明。

最小试验：在可丢弃项目做一项熟悉任务，准备 AGENTS＋交接文档基线与插件条件，各换一次新会话；记录恢复到正确下一步的人工分钟、引用正确率、最终任务合格率、重复读文件、提示用量和索引资源。保持模型、任务信息和预算一致，放一条过期经验检验纠错。若检索变多但办结不快、误引用上升或清理成本过高，则不继续扩大。首次试用不主动开启查询扩展、反思或扩大跨项目经验范围。
