# 研究数据契约

本契约只解释字段语义与数据不变量；版本及结构以对应 Schema 为准：
[档案](../schemas/catalog.schema.json)、[观察批次](../schemas/observations.schema.json)、
[研究会话](../schemas/research-session.schema.json)、[运行清单](../schemas/run-manifest.schema.json)、[发布输入](../schemas/publication.schema.json)、
[META](../schemas/github-meta.schema.json)、[受阻记录](../schemas/research-block.schema.json)。未知字段、重复 JSON 键及非法日期均拒绝。

## 唯一当前快照与本轮增量

- 当前快照是唯一正式研究真相：当前插件档案、来源状态，以及它引用的当前分析、必要证据和持久受阻状态。唯一性指逻辑上只有一套权威现状，不要求所有材料塞进一个 JSON；生成页面和本轮工作副本不构成第二真相。
- 新一轮只读当前快照作为比较基线，记录摘要；不要求历史会话、历史 manifest 或 runs 归档。当前来源成员清单或比较维度缺失时记 unknown，不能凭研究子集推断全目录移除。
- 本轮先独立生成观察、分析、证据和进度，再合成候选快照。逐项完成只更新本轮暂存区；正式快照在最终合并前保持可用。
- 合并必须校验基线摘要、身份、来源与代码版本、证据引用、结论依赖及生成一致性。基线变化须重新计划；重复应用同一增量不得重复追加事实。
- 合并以一致的事务提交当前档案、分析／证据引用和展示输入；多文件准备阶段不能对外暴露部分新状态，失败仍使用旧快照。实现必须有可回读的提交点及中断恢复办法。
- 未选、失败或未完成项不替换有效的当前记录，不因本轮 pending／blocked 删除旧成果；新证据证明旧结论失效时，可将经过校验的失效记录合并为待复核状态，不伪造完成态。
- 当前结论保留来源 URL、固定版本、证据类型、限制及必要材料。合并时将仍需引用的材料落入正式快照位置，不让有效结论依赖可清理的 runs 路径。
- 合并回读成功且当前快照可独立校验、生成页面后，本轮不再被引用的材料可清理；未合并增量保留用于恢复。历史变迁由 Git 追踪，不要求每轮永久归档；本规则不自动授权删除既有文件。

正式快照采用 v3 组件存储，由 [组件存储 Schema](../schemas/component-storage.schema.json) 约束：

- `data/catalog/index.jsonl` 每行一个紧凑 JSON，按小写32位 `id` 升序，末尾换行；覆盖已研究组件与尚未研究的发现候选。包含身份、仓库、名称、分类、标签、可用性、研究层级、推荐结论／理由／分数／有效性、发布状态、稳定详情目录及组件文件字节 SHA-256。推荐页仍经过当前研究与依赖有效性校验，不直接按索引分数取榜。
- `data/catalog/components/<id前两位>/<id>.json` 为该组件的完整记录，UTF-8、`indent=4`、末尾换行。`id = md5(UTF8(identity))`，`identity = github:<仓库数字ID>:<组件ID>`，不使用仓库名、路径或大小写转换重算身份；写入时检查 MD5 冲突。`data` 聚合档案、发现记录、报告原文、META、推荐评估、发布记录／摘要／能力／建议、详情目录及受阻记录；缺失部分不伪造。尚未研究候选索引标记 unassessed，分数为 null。
- `data/catalog/state.json` 只保存全局来源、限制、事务标识、必要证据映射及逻辑数组的原始顺序，绑定索引字节摘要和完整语义摘要。它不另存组件档案。
- `data/catalog/evidence/<sha256前两位>/<sha256>.json` 保存必要证据正文，按内容复用；原证据路径作为稳定引用标签保留，读取器通过映射取得内容。缺失原件仍列 unavailable_artifacts，不将迁移当作新验证。

共享 `snapshot-storage.mjs` 校验格式、身份、排序、路径、符号链接、详情／证据摘要及索引派生字段，还原 [snapshot Schema](../schemas/snapshot.schema.json) 定义的 v1 逻辑对象供业务使用。逻辑对象内已有 `id`、依赖 `plugin_id` 和证据 ID 保留原身份字符串，避免改写研究证据与 WORK 基线；物理存储和索引的 `id` 统一为 MD5。索引字段由组件完整记录派生，不单独维护名单。旧 v1／v2 只由兼容读取器用于显式迁移。
本轮完整逻辑状态由 [工作文件 Schema](../schemas/snapshot-work.schema.json) 约束，拆分入口、队列、状态和兼容链接由 [存储 Schema](../schemas/work-storage.schema.json) 约束。新建过程使用 v2 拆分存储：WORK 只保存 base_digest、INPUT／QUEUE／会话状态／单项记录的路径和 SHA-256；INPUT 保存唯一完整候选清单，QUEUE 保存按输入下标分组的变化及缺席项，状态文件只保存会话头与非默认状态／检查点，已完成记录逐项独立保存。SESSION.json 是指向同目录 WORK 的兼容入口，不另存完整清单。
读取器校验引用路径、内容摘要、Schema、队列覆盖、选择和检查点后，重建原 v1 内存结构；内存结构的语义摘要保持不变，不因拆文件改变已有合并计划、事务标识或结论。session.base_digest 仍绑定正式快照，previous_digest 仅兼容旧工具。
过程依赖对象按内容摘要命名且不可变，更新先准备依赖、再原子替换唯一 WORK 索引；中断前后读取旧／新完整状态。SESSION 入口通过 WORK 读取当前会话，不独立切换状态；未引用的中断残留不当作完成记录。引用只能落在本轮目录，拒绝路径逃逸、符号链接逃逸与摘要不符，不自动修正损坏内容。
旧 v1 可继续读取；显式 `snapshot migrate-work --work ...` 只预览，加 `--apply` 才迁移。先保留 WORK／SESSION 原始字节到本轮 migration-originals，再生成、回读并核对完整语义摘要后切换 WORK；重复执行不得覆写备份或重置选择／状态。迁移不依赖当前正式基线仍匹配，也不执行研究或修改 SNAPSHOT。正常暂存旧 v1 保持旧格式，避免隐式迁移。
合并计划从固定基线和经过校验的 WORK 重建结果；持有 `index.jsonl.lock` 后复核基线、WORK 与结果摘要。共享写入器先在内存准备并回读完整候选，再在 `.transaction/` 保存所有变更文件的旧字节及撤销清单，逐文件原子替换，最后更新 state 与 index 并核对完整语义摘要。事务存在期间读取拒绝返回部分状态，成功后清除撤销清单；普通写入失败自动回滚，中断后核实无活动写入者、处理遗留锁，再执行 `npm run snapshot -- recover-storage` 回滚。读取结束再次核对索引及事务状态，变化时拒绝并要求重读。`.transaction/` 不进入 Git，不可当缓存删除。重复 apply 返回 already_applied，不追加研究事实；无内容变化不重写文件。

使用 `npm run snapshot -- migrate-storage --backup data/runs/<round>/migration-originals/catalog-v2/SNAPSHOT.json` 显式迁移旧正式快照，持有相同锁，保存旧索引及旧引用图原始字节后生成新组件存储，回读核对完整语义摘要；重复执行只校验新存储。清理旧索引及其条目前，应备份整个旧引用图并确认语义与生成结果一致。迁移不改变 WORK 基线、检查点、推荐评分、研究版本或原证据。`PLUGINS.json`、`PUBLICATION.json`、`PLUGIN-PATHS.json` 和展示目录下的 `META.json` 不再生成；META 直接从组件文件读取。页面从当前快照重建，生成中断可重跑，生成物不反向覆盖快照。当前研究有效性来自 records 与 catalog 的分析摘要匹配，不来自旧 manifest。

## 身份与分类

- `identity = github:<repository_id>:<component_id>`，物理 `id = md5(identity)`；仓库数字 ID 与已分配组件 ID 是身份，名称和路径不是。
  改名、路径移动保留身份，旧位置进入 `aliases`；相同 URL 下重建而数字 ID 不同的仓库是另一身份。
- 同仓库不同组件可分别建档；`entry_type` 表示条目类型，技术主类与业务主类各一个，`tags` 可多个。
  分类含义由[研究规范](../../dsh-plugin-insight/references/RESEARCH-STANDARD.md)定义，目录收录不证明可安装。

## 指纹、来源与证据

- `fingerprints` 保存各方面最后一次成功核查的内容版本：`directory` 为目录条目，`code` 为代码，
  `release` 为发布版本及产物，`compatibility` 为支持声明及已验证环境，`maintenance` 为维护状态。
  指纹是固定提交、文件树／文件 SHA 或确定性内容哈希，不能用采集时间代替；未检查的方面省略并保留旧值。
  默认分支与发布包的指纹不可互相冒充。
- `sources` 绑定 URL、`revision` 与 `retrieved_at`；`membership` 表示该来源的 present／removed／unknown。
  来源按 URL 比较最新成功快照，一个来源缺席不代表所有来源均已移除。
  发现基线中本轮缺席的候选，只有其已知相关来源均完整核查时才剔除；否则保留旧身份与指纹供下一轮按 unknown 比较，包括尚未进入 catalog 的候选。候选本轮仍出现时，也要保留其来自未完整核查来源的既有成员关系，并标为待复核；只有该来源完整核查且候选缺席才能移除该来源关系。最新 discovery 来源成员集合与最后完成研究的版本比较基线分别保存，不改写本轮固定输入或选择。
- 同一来源／证据 ID 不得复用为不同内容，内容变化使用新 ID。证据 ID 全局唯一，来源 ID 在插件内唯一。
  当前快照保留支撑有效结论的对象；无当前引用的历史材料不要求永久累积，清理须检查引用完整性。本轮候选复用合并器的身份、来源与依赖校验，正式快照不累计 runs 日志。
  完整复核成功的组件以本轮来源和证据替代过期集合；仍被其他当前结论引用的证据保留。嵌入原件与缺失原件清单同步按当前引用收敛，不随每轮永久增长。
- 证据 `kind` 区分作者声明、源码核查、本地测试、真实宿主验收与独立反馈，均绑定版本并记录边界。
  `artifact` 引用材料；执行证据还必须有 `environment` 与执行结果文件，材料不得保存凭据。
- `research_depth` 的 catalog／source／tested／host_verified 表示已有证据层级；提高层级须有对应证据。
  历史执行证据不自动证明当前版本通过，源码与作者声明不等于运行效果。

## 结论与依赖

- `findings` 保存主题、结论、判断性质、`evidence_ids`、`dependencies`、`reviewed_at` 与状态。
  依赖绑定稳定插件 ID、核查方面及当时指纹，跨插件比较必须记录相关对象的依赖。
- 生态供给结论也依赖来源总体指纹，可将目录作为 `resource` 条目并依赖其 `directory` 指纹；
  目录变化不冒充单个插件代码变化。
- 贡献、关键质疑和新创新假设的论证复用现有 `findings` 主题与判断性质，完整推导写入报告；两轴创新评分使用下述 `innovation_scores`，不将新假设转成插件已有贡献。
  `basis` 按实际支持程度选择；未验证的新假设不得标为 `supported`，在文本中说明推导依据和未验证部分。`evidence_ids` 引用推导依据不表示假设已被验证；探索性设想不得冒充已有贡献。
- `needs_review` 表示依赖变化后待复核，不表示结论已被证伪；原文和证据保留。
  只有显式更新依赖、证据与复核时间的结论才能恢复有效，普通采集不自动解除失效状态。

## 创新评分数据

- 当前插件的 `innovation_scores` 保存唯一评分真相，结构见 catalog Schema；评分方法仅由洞察 Skill 的[研究规范](../../dsh-plugin-insight/references/SCORING-STANDARD.md#创新评分标准innovation-v1)维护，发布输入不复制评分。
- 保存 `rubric`、固定源码 `revision`、`reviewed_at`、`status` 和 `dependencies`；technical／business 各含 criteria、score、rationale、basis、evidence_ids。分项缺失用null，任何分项为null时该轴score必须为null；其余情况下score必须等于分项和。
- 数值必须符合对应权重的档位，理由非空，引用本插件已有证据；数值轴须有可核查证据及supported／interpretation判断性质，unverified不能携带数值轴总分。评分复核时间不得晚于插件检查时间。current评分须有对应revision的源码核查证据及自身code指纹依赖，引用的依赖必须可定位。
- 评分进入分析摘要绑定；修改评分须同步当前记录的analysis摘要。新研究stage要求显式提交本轮两轴评分（允许null及缺口说明），版本必须匹配，复核时间不得早于会话截止时间。
- 依赖失效将评分置为needs_review，不自动清零、继承为新版本有效评分或重新打分；新观察省略评分时保留已有评分并按依赖判断失效。人工重新复核后才能恢复current。
- 兼容无评分的历史档案，不因加入此字段自动为历史插件补分或刷新复核时间。未评分、分项未知、版本不匹配或待复核的评分均不参与数值排序。原始评分和评分理由仅保存在JSON，不展示到读者Markdown。

## 组件推荐结论与评分

每个正式档案组件保存 `recommendation`，与 META 客观采集、创新评分分开；字段结构见 catalog Schema。研究由 AI 执行时记录 evaluator=ai，不把 AI 判断表述成人类已经审核。

- `decision` 为 unassessed（未评估）、not_recommended（不推荐）、observe（观察）、trial（试用）、install（值得安装）。不在推荐页不等于不推荐；不可从旧名单缺席推断结论。
- `reason` 用一行说明适合谁、推荐或不推荐的理由及关键条件。已评估项保存 adoption-v1 的四项 criteria（score、rationale）、总分 score、固定 revision、独立 reviewed_at、evaluator、evidence_ids 和 dependencies。推荐复核时间独立于源码检查时间，不借此刷新研究截止时间。
- 未评估项 reason 说明缺口，score、criteria、revision、reviewed_at、evaluator 为 null，证据与依赖为空，status=current；null 不是0。已评估项必须有完整分项、数值总分和同版本源码证据。评分方法与结论含义见[研究规范](../../dsh-plugin-insight/references/SCORING-STANDARD.md#采用推荐评分adoption-v1)。
- status=current／needs_review 表示结论有效性，不增加第六种推荐结论。当前推荐须匹配自身 code 指纹、固定分析版本与全部依赖；依赖变化保留原分和理由并置 needs_review，不自动升降级。脚本变化标记另由 META 控制暂停入榜。
- install 的引用证据必须包含同版本、带 artifact 和 environment 的 host_acceptance；高分不能绕过验收。真实安装、核心功能与禁用／卸载内容仍须逐项审阅。
- 新研究 stage 必须显式提交已评估的本轮结论、四项评分及理由，不接受 unassessed；总分由脚本求和，不能以创新分、Star、下载量或关键词推断。旧观察允许缺字段以供恢复；正式迁移逐项补 unassessed，只有已实际评估的项补分。
- 推荐对象从全部当前有效 publication.records 关联的 catalog 组件中派生，不维护独立名单；仅 current、版本一致、无待复核结论且 decision 为 trial／install 的非空评分项参与。排序与上限见输出标准。历史 publication.recommendations 仅兼容读取，当前生成器忽略，后续正式合并删除该字段；DISPLAY 不再提交名单。
- 推荐属于分析摘要；变更需同步发布记录的 analysis_sha256。仅复核推荐可使用 `snapshot assess-recommendations`，绑定正式基线及各项固定版本，持锁验证并原子合并，不改变原稿、检查时间或伪造新研究。保留档案但缺少有效发布记录的组件，只能依据已有固定版本源码证据补观察／不推荐结论及评分，并强制needs_review；不恢复发布、不将历史源码证据改标为当前版本。输入、预览及恢复见[会话操作](../../dsh-plugin-init/references/SESSION-OPERATIONS.md#组件推荐迁移与复核)。

## 观察批次与候选合并

- 批次先写入本轮暂存区，提交成功检查对象的完整当前元数据；来源、证据、结论可只提交新增或复核部分。
  `findings: []` 保留已有结论，不表示删除。未检查对象不写入，失败对象进入 `errors`。
- `run_id` 唯一标识一次检查；同 ID 不得重复应用。`last_checked_at` 只在成功检查后更新，且不得晚于批次 `checked_at`，
  也不得早于档案已有检查时间。纯错误批次只追加失败记录，不改变插件档案。
- 来源移除或仓库归档保留稳定身份及明确的当前状态；超时、403、404、截断不能推断删除或不可用。
  `init` 仅适用于空档案，`update` 用于已有档案；两者均不物理删除历史条目。
- 写入必须同时满足基础档案摘要、候选结果摘要及结构约束，拒绝过期计划、损坏计划和并发覆盖。
  档案与会话写入采用独占锁和原子替换；已有锁不得被自动抢占。

## 持久受阻与重试

- 正式快照可含 `research_blocks` 映射，按稳定组件ID保存最近一次受阻，独立于完成研究档案和发布记录。旧快照没有此字段等价于无已登记受阻，不强制改写历史。
- 每项按受阻Schema保存 `plugin_id`、固定 `revision`（未知为null）、稳定 `reason_code`、可读 `reason`、自包含 `details`、`blocked_at` 与登记轮次 `run_id`。详情保留问题文件、错误/必要字节事实、固定版本出处和下一步，不只引用本机runs路径；不保存凭据。原因代码描述稳定故障类别，不以时间、原始报错措辞或轮次生成新代码。
- block先写本轮所选条目的 `block` 及blocked状态，最终plan/apply与研究成果一起持久化；全轮只有受阻记录也可合并，不伪造成功研究。失败不覆盖已有有效报告/展示；后续成功stage并合并才清除该组件的旧受阻。新版本再次失败则替换为新版本原因，历史由Git追踪。
- 新轮次候选的非空代码版本与正式受阻版本相同时，沿用已知原因，默认放入 `selection.suppressed_ids`，不准备材料、不调用洞察、不占额度。只有目录、热度或报错描述变化不触发重试；未重新处理不能声称已确认故障消失或原因变化。未知版本不作同版本去重。
- 版本变化恢复正常增量候选资格，仍按额度和顺序选择。用户明确要求重试时，`snapshot start --retry-plugin <稳定ID>`（可重复）固定 `selection.retry_ids`，指定项优先、去重后占正常额度，超额度或非已登记受阻候选则拒绝；不能用重试扩充额度。相同版本的环境/统计器修复也通过显式重试处理，不每轮自动试探。
- 同轮恢复保持固定选择和跳过集合；仅用户明确要求时可用 `snapshot retry --work ... --plugin ...` 将尚未合并的已选blocked项重置pending，删除本轮block后重新准备，保留原始失败文件。未选/已完成项不接受retry；已合并轮次通过新轮显式重试，不修改旧事务。
- 选择绑定正式快照摘要与上述跳过/重试集合；合并时重新计算核对，不允许随意填入跳过ID绕过研究。已知受阻跳过数量、本轮受阻数量和完成数量分别报告；跳过不算完成或本轮失败。

## 本轮会话与检查点

- 会话 `id` 标识本轮增量，`checked_at` 为本轮检查基准时间；新轮次绑定当前快照摘要，同轮续跑保留选择和完成材料。
  现有 `previous_digest` 仍表示旧实现中的对照会话摘要，不能冒充当前快照摘要；它不再是新流程必须提供历史会话的理由。
- 会话输入从固定版本的目录条目生成；YAML／Markdown 解析、仓库数字 ID、规范仓库名、组件路径及目录条目摘要都须可追溯。
  GitHub 重定向或改名按数字 ID 合并，不能把同一仓库的旧新名称当作两个对象；组件 ID 优先复用当前档案中同一数字仓库和路径的既有分配。
  新路径规范化得到的组件 ID 若已分配给同仓库其他路径，必须记录问题并停止分配，不能推断为组件移动。
  无法解析条目、核实身份或确认默认分支时保存问题记录，并将受影响来源视为不完整，不静默漏项或据此推断移除。
- 来源 `complete` 表示本轮范围内完整读取，不表示插件可用；未知来源／代码 `revision` 为 null，不能编造版本。
  候选的 `source_urls` 必须对应会话来源，身份、路径与指纹保持可追溯。
- `changes` 中 added 表示当前基线没有该身份；moved、content_changed、sources_changed 分别表示位置、内容指纹和来源变化。
  无变化为 unchanged，不能确认则为 unknown。仅当基线中相关来源已知且本轮均完整核查且候选缺席，才可标记 removed_from_source。
  缩小范围不算生态删除；变化标记可重叠，不能相加为对象总数，也不能据此免除本轮重新分析。
- 新轮次使用 `selection.mode = incremental`，将基线中已有完成研究记录（含保留完整研究原稿、因失效退出当前展示的项）的 ID 固定在 `selection.researched_ids`，其中结论已失效或尚未恢复当前展示记录的待复核 ID 固定在 `selection.review_required_ids`；两者必须与正式基线一致。目录中已发现但从未完成研究的条目仍是新研究项。
  先比较全部已有成果与本轮输入；有变化、缺席无法确认、指纹未知或依赖失效的已有项进入更新队列，确认未变的已有项保留原成果且不占额度。比较基线取该项最后完成研究的记录，不能取后来只发现而未完成研究的版本。
  先排除正式同版本受阻项，将显式重试项按输入顺序置前，再按完整输入顺序排列更新队列（缺席项追加其后）和尚无完成研究记录的新项，去重后按此顺序固定 `selected_ids`。
  `research_limit` 表示更新与新项的总额度，必须为正安全整数；新调用省略参数时默认40，并在新会话中显式保存40。历史会话未保存额度时保持原有选择语义，不在恢复时套用新默认值。额度40、待更新 n≤40时补充最多40−n个新项；n>40时先做40个更新项，剩余更新留待后轮。新项不足时允许少于额度。
  `selected_ids` 在增量模式总是存在（允许空数组）；`selectedItems` 按固定选择顺序返回。未带 `selection` 的既有会话继续按旧的前 N 项语义校验和恢复，不反写历史选择。
  本轮选中后首次受阻的项仍占名额，续跑不补位、不重置；正式同版本受阻在选择前跳过，不占新轮名额；未选项保留 pending，但不接受完成、受阻或重试状态变更。
- 新会话条目从 pending 开始；blocked 带受阻原因，complete 必须带检查点。
  所选范围的 complete／blocked／total 与完整列表 listed、未选 deferred 分开统计，不能把未选条目称作已研究。
- 检查点绑定本轮已暂存并验证的观察批次、运行 ID、固定版本与材料摘要；候选档案必须匹配提交的指纹、证据和检查时间。
  本轮结论须显式复核，时间不早于会话基准，并有对应版本源码证据；时间较新本身不证明研究已完成。
  无固定版本或无源码核查不能成为 complete，材料不存在或摘要不符即失效，不得静默覆盖原件。
- start 后的会话候选、来源、指纹和选择属于本轮固定事实。暂存候选若与会话不一致，应诊断观察批次或输入错误，
  不得把当前档案指纹反向写回会话来通过 checkpoint。只改变格式的历史修复走显式迁移，不复制旧会话并伪造新的检查时间或研究轮次。
- 会话完成表示本轮记录已准备好，最终合并状态另行回读确认；不表示目标插件验收通过。只读队列选择不提供并发认领语义。

本轮会话、观察批次和准备材料存放在 Git 忽略的 `data/runs/`，用于合并前恢复。新流程的当前快照必须包含持续使用所需的分析和证据，不靠历史会话证明其有效性。
历史 manifest 只用于首次迁移或可选审计；当前生成器、校验和新轮次均只依赖正式快照。记录完成时仍验证本轮检查点，合并后不需要 runs。

## 发布输入、META 与统计字段

- 发布输入只组织已有成果，不成为研究事实或结论的替代真相源；推荐对象由已完成项的组件推荐结论派生。
  `metadata` 以稳定插件 ID 关联快照，仓库数字 ID 和名称必须匹配；`history` 兼容旧输入。
  现有可选 `catalog` 与 `history` 字段仅兼容旧输入，不作为新流程的历史依赖；首次 added 仅表示本工程入档，不代表 npm 发布。
- 发布输入 `summaries` 按插件 ID 绑定作者功能材料的归纳文本、来源 URL 和固定版本；它不是独立验证结论，也不冒充逐字引文。
- 发布输入 `capabilities` 绑定固定版本的人工确认能力条目；省略项不表示已确认数量为零。
- 发布输入 `advice` 是按插件 ID 保存的读者版使用建议；`revision` 必须与研究提交一致，`text` 只润色表达，不改变证据事实或当前结论。
- META 的 `captured_at` 是采集时间，`pushed_at` 是仓库推送时间，两者不能混用。
  缺失／失败值为 null 并保留错误，不用 0 代替未知；GitHub 与 npm 各自时间及窗口独立保留。
- 可选 `npm` 绑定已核实的 `package_name`、下载量、窗口、来源与错误；缺少该对象不等于下载量为零。
  返回包名、窗口与非负整数下载数须匹配，否则记未知；下载量不等于用户数。
- `npm.publication` 的 first_published_at 来自已核实包的注册表 time.created，表示首次发布，仅保留为数据。可选的 latest_version、latest_published_at、latest_error 必须成组出现，来自注册表 dist-tags.latest、该版本的 time[version] 及版本条目身份核对；不是 time.modified、任意最高版本或 Git 推送时间。成功时版本与日期同时存在且 latest_error 为 null，失败时两者为 null 并保存错误。首次时间与最新版本采集可独立失败；旧快照缺少 latest 字段时视为未知，不回退首次时间。采集时间及注册表来源共用 publication.captured_at／source_url，缺失或失败不从入档、Git 或下载量推断。
- `refresh:meta -- --npm-publication-only` 仅重采既有已确认包名的 publication，保留下载、GitHub指标、脚本更新检查、研究记录与推荐，仍经基线摘要、完整校验、独占锁及原子快照写入；默认每日完整META刷新也采集最新版本字段。
- 可选 `code_update` 绑定研究基线、当前提交、变更路径和核查时间；`script_changed` 为 true／false／null 三态。
  它表示待重新洞察的脚本变化，独立于 findings 的依赖失效状态，不改写研究深度或完成检查点。
- 工程统计的 `revision`／`component`／`coverage` 界定版本、组件及完整或抽读范围；工具版本、内容摘要与排除项须保留。
  静态能力候选不是正式能力数，`confirmed_count: null` 表示未确认，不能转成 0；统计材料同样不可覆盖检查点已绑定的原件。

## 路径、兼容与清理

- 稳定身份与物理目录分离，路径注册表使改名／移动不改变当前入口；轮次目录只标识本轮工作区。
- 未完成增量的证据、报告和检查点不能静默覆写。需要修正时先解除该项完成状态并重新校验，不能只刷新摘要掩盖内容变化。
- 已合并记录的后续变化通过新增量替换当前状态，旧状态可由 Git 查询；不要求重新创建旧轮次或保留所有本地原件。
- 清理前检查当前引用、未合并状态与活动锁；当前仍引用的材料先迁入正式位置并校验，再清理过程副本。
- 旧迁移记录及清理脚本仅适用于其原有归档格式。适配新模型前不得用旧工具扩大删除范围，也不得删除现有材料来绕过校验。更新规范本身不执行数据迁移。

## 逐题研究材料与正式报告

新单插件装配输入的 research_questions 由[问题交付 Schema](../schemas/research-questions.schema.json)约束，研究执行以[逐题流程](../../dsh-plugin-insight/references/QUESTION-WORKFLOW.md)为准。它是研究输入与过程结构，不新增 catalog 字段，不改既有分析摘要或身份。逐题完整回答、状态、固定版本证据定位与原文、未知项必须写入正式 reports；源材料仍通过 artifacts 保存。主题覆盖、文本、ID和源码位置可机械校验，论证充分性与结论真实性须逐题审阅。

已合并的当前研究不能依赖 PLAN、逐题本地文件或 ANALYSIS 存在；清理过程副本前验证正式报告和必要证据足以独立回读。历史报告缺少逐题结构时保持原状态，不从旧摘要补造研究，不因展示重生成升级研究深度或验收状态。
