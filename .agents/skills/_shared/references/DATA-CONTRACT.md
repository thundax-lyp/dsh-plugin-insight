# 研究数据契约

本契约只解释字段语义与数据不变量；版本及结构以对应 Schema 为准：
[档案](../schemas/catalog.schema.json)、[观察批次](../schemas/observations.schema.json)、
[研究会话](../schemas/research-session.schema.json)、[运行清单](../schemas/run-manifest.schema.json)、[发布输入](../schemas/publication.schema.json)、
[META](../schemas/github-meta.schema.json)。未知字段、重复 JSON 键及非法日期均拒绝。

## 唯一当前快照与本轮增量

- 当前快照是唯一正式研究真相：当前插件档案、来源状态，以及它引用的当前分析和必要证据。唯一性指逻辑上只有一套权威现状，不要求所有材料塞进一个 JSON；生成页面和本轮工作副本不构成第二真相。
- 新一轮只读当前快照作为比较基线，记录摘要；不要求历史会话、历史 manifest 或 runs 归档。当前来源成员清单或比较维度缺失时记 unknown，不能凭研究子集推断全目录移除。
- 本轮先独立生成观察、分析、证据和进度，再合成候选快照。逐项完成只更新本轮暂存区；正式快照在最终合并前保持可用。
- 合并必须校验基线摘要、身份、来源与代码版本、证据引用、结论依赖及生成一致性。基线变化须重新计划；重复应用同一增量不得重复追加事实。
- 合并以一致的事务提交当前档案、分析／证据引用和展示输入；多文件准备阶段不能对外暴露部分新状态，失败仍使用旧快照。实现必须有可回读的提交点及中断恢复办法。
- 未选、失败或未完成项不替换有效的当前记录，不因本轮 pending／blocked 删除旧成果；新证据证明旧结论失效时，可将经过校验的失效记录合并为待复核状态，不伪造完成态。
- 当前结论保留来源 URL、固定版本、证据类型、限制及必要材料。合并时将仍需引用的材料落入正式快照位置，不让有效结论依赖可清理的 runs 路径。
- 合并回读成功且当前快照可独立校验、生成页面后，本轮不再被引用的材料可清理；未合并增量保留用于恢复。历史变迁由 Git 追踪，不要求每轮永久归档；本规则不自动授权删除既有文件。

正式真相存储在 `data/catalog/SNAPSHOT.json`，由 [snapshot Schema](../schemas/snapshot.schema.json) 约束，内含 catalog、publication、registry、discovery、reports、metadata、artifacts、迁移限制及最近一次合并标识。必要原件以内容和 SHA-256 嵌入；旧缺失原件单列 unavailable_artifacts，不要求找回，也不能被新记录用作缺失证据的豁免。
本轮 WORK 由 [工作文件 Schema](../schemas/snapshot-work.schema.json) 约束，包含固定 input、session、base_digest 和已完成记录；新增 session.base_digest 绑定正式快照，previous_digest 仅兼容旧工具。
合并计划从固定基线和经过校验的 WORK 重建结果；持有独占锁后复核基线、WORK 与结果摘要，原子替换单个 SNAPSHOT 文件，再回读。中断最多留下旧／新两个完整状态之一；遗留锁须人工核实。重复 apply 同一结果返回 already_applied，不追加历史运行日志。
PLUGINS、PUBLICATION、PLUGIN-PATHS、META 及页面从快照重建，生成前后核对快照摘要；生成中断可重跑，兼容输出不反向覆盖快照。当前研究有效性来自 records 与 catalog 的分析摘要匹配，不来自旧 manifest。

## 身份与分类

- `id = github:<repository_id>:<component_id>`；仓库数字 ID 与已分配组件 ID 是身份，名称和路径不是。
  改名、路径移动保留身份，旧位置进入 `aliases`；相同 URL 下重建而数字 ID 不同的仓库是另一身份。
- 同仓库不同组件可分别建档；`entry_type` 表示条目类型，技术主类与业务主类各一个，`tags` 可多个。
  分类含义由[研究规范](../../dsh-plugin-insight/references/RESEARCH-STANDARD.md)定义，目录收录不证明可安装。

## 指纹、来源与证据

- `fingerprints` 保存各方面最后一次成功核查的内容版本：`directory` 为目录条目，`code` 为代码，
  `release` 为发布版本及产物，`compatibility` 为支持声明及已验证环境，`maintenance` 为维护状态。
  指纹是固定提交、文件树／文件 SHA 或确定性内容哈希，不能用采集时间代替；未检查的方面省略并保留旧值。
  默认分支与发布包的指纹不可互相冒充。
- `sources` 绑定 URL、`revision` 与 `retrieved_at`；`membership` 表示该来源的 present／removed／unknown。
  来源按 URL 比较最新成功快照，一个来源缺席不代表所有来源均已移除。
  发现基线中本轮缺席的候选，只有其已知相关来源均完整核查时才剔除；否则保留旧身份与指纹供下一轮按 unknown 比较，包括尚未进入 catalog 的候选。不改写本轮固定输入或选择。
- 同一来源／证据 ID 不得复用为不同内容，内容变化使用新 ID。证据 ID 全局唯一，来源 ID 在插件内唯一。
  当前快照保留支撑有效结论的对象；无当前引用的历史材料不要求永久累积，清理须检查引用完整性。本轮候选复用合并器的身份、来源与依赖校验，正式快照不累计 runs 日志。
  完整复核成功的组件以本轮来源和证据替代过期集合；仍被其他当前结论引用的证据保留。嵌入原件与缺失原件清单同步按当前引用收敛，不随每轮永久增长。
- 证据 `kind` 区分作者声明、源码核查、本地测试、真实宿主验收与独立反馈，均绑定版本并记录边界。
  `artifact` 引用材料；执行证据还必须有 `environment` 与执行结果文件，材料不得保存凭据。
- `research_depth` 的 catalog／source／tested／host_verified 表示已有证据层级；提高层级须有对应证据。
  历史执行证据不自动证明当前版本通过，源码与作者声明不等于运行效果。

## 结论与依赖

- `findings` 保存主题、结论、判断性质、`evidence_ids`、`dependencies`、`reviewed_at` 与状态。
  依赖绑定稳定插件 ID、核查方面及当时指纹，跨插件比较必须记录相关对象的依赖。
- 生态供给结论也依赖来源总体指纹，可将目录作为 `resource` 条目并依赖其 `directory` 指纹；
  目录变化不冒充单个插件代码变化。
- `needs_review` 表示依赖变化后待复核，不表示结论已被证伪；原文和证据保留。
  只有显式更新依赖、证据与复核时间的结论才能恢复有效，普通采集不自动解除失效状态。

## 观察批次与候选合并

- 批次先写入本轮暂存区，提交成功检查对象的完整当前元数据；来源、证据、结论可只提交新增或复核部分。
  `findings: []` 保留已有结论，不表示删除。未检查对象不写入，失败对象进入 `errors`。
- `run_id` 唯一标识一次检查；同 ID 不得重复应用。`last_checked_at` 只在成功检查后更新，且不得晚于批次 `checked_at`，
  也不得早于档案已有检查时间。纯错误批次只追加失败记录，不改变插件档案。
- 来源移除或仓库归档保留稳定身份及明确的当前状态；超时、403、404、截断不能推断删除或不可用。
  `init` 仅适用于空档案，`update` 用于已有档案；两者均不物理删除历史条目。
- 写入必须同时满足基础档案摘要、候选结果摘要及结构约束，拒绝过期计划、损坏计划和并发覆盖。
  档案与会话写入采用独占锁和原子替换；已有锁不得被自动抢占。

## 本轮会话与检查点

- 会话 `id` 标识本轮增量，`checked_at` 为本轮检查基准时间；新轮次绑定当前快照摘要，同轮续跑保留选择和完成材料。
  现有 `previous_digest` 仍表示旧实现中的对照会话摘要，不能冒充当前快照摘要；它不再是新流程必须提供历史会话的理由。
- 会话输入从固定版本的目录条目生成；YAML／Markdown 解析、仓库数字 ID、规范仓库名、组件路径及目录条目摘要都须可追溯。
  GitHub 重定向或改名按数字 ID 合并，不能把同一仓库的旧新名称当作两个对象；组件 ID 优先复用当前档案中同一数字仓库和路径的既有分配。
  新路径规范化得到的组件 ID 若已分配给同仓库其他路径，必须记录问题并停止分配，不能推断为组件移动。
  无法解析条目、核实身份或确认默认分支时保存问题记录，并将受影响来源视为不完整，不静默漏项或据此推断移除。
- 来源 `complete` 表示本轮范围内完整读取，不表示插件可用；未知来源／代码 `revision` 为 null，不能编造版本。
  候选的 `source_urls` 必须对应会话来源，身份、路径与指纹保持可追溯。
- `changes` 中 added 表示当前基线没有该身份；moved、content_changed、sources_changed 分别表示位置、内容指纹和来源变化。
  无变化为 unchanged，不能确认则为 unknown。仅当基线中相关来源已知且本轮均完整核查且候选缺席，才可标记 removed_from_source。
  缩小范围不算生态删除；变化标记可重叠，不能相加为对象总数，也不能据此免除本轮重新分析。
- 新轮次使用 `selection.mode = incremental`，将基线中已有完成研究记录（含保留完整研究原稿、因失效退出当前展示的项）的 ID 固定在 `selection.researched_ids`，其中结论已失效或尚未恢复当前展示记录的待复核 ID 固定在 `selection.review_required_ids`；两者必须与正式基线一致。目录中已发现但从未完成研究的条目仍是新研究项。
  先比较全部已有成果与本轮输入；有变化、缺席无法确认、指纹未知或依赖失效的已有项进入更新队列，确认未变的已有项保留原成果且不占额度。比较基线取该项最后完成研究的记录，不能取后来只发现而未完成研究的版本。
  按完整输入顺序排列更新队列（缺席项追加其后），再排列尚无完成研究记录的新项，去重后按此顺序固定 `selected_ids`。
  `research_limit` 表示更新与新项的总额度，必须为正安全整数；新调用省略参数时默认40，并在新会话中显式保存40。历史会话未保存额度时保持原有选择语义，不在恢复时套用新默认值。额度40、待更新 n≤40时补充最多40−n个新项；n>40时先做40个更新项，剩余更新留待后轮。新项不足时允许少于额度。
  `selected_ids` 在增量模式总是存在（允许空数组）；`selectedItems` 按固定选择顺序返回。未带 `selection` 的既有会话继续按旧的前 N 项语义校验和恢复，不反写历史选择。
  受阻项占名额，续跑不补位、不重置；未选项保留 pending，但不接受完成、受阻或重试状态变更。
- 新会话条目从 pending 开始；blocked 带受阻原因，complete 必须带检查点。
  所选范围的 complete／blocked／total 与完整列表 listed、未选 deferred 分开统计，不能把未选条目称作已研究。
- 检查点绑定本轮已暂存并验证的观察批次、运行 ID、固定版本与材料摘要；候选档案必须匹配提交的指纹、证据和检查时间。
  本轮结论须显式复核，时间不早于会话基准，并有对应版本源码证据；时间较新本身不证明研究已完成。
  无固定版本或无源码核查不能成为 complete，材料不存在或摘要不符即失效，不得静默覆盖原件。
- start 后的会话候选、来源、指纹和选择属于本轮固定事实。暂存候选若与会话不一致，应诊断观察批次或输入错误，
  不得把当前档案指纹反向写回会话来通过 checkpoint。只改变格式的历史修复走显式迁移，不复制旧会话并伪造新的检查时间或研究轮次。
- 会话完成表示本轮记录已准备好，最终合并状态另行回读确认；不表示目标插件验收通过。只读队列选择不提供并发认领语义。

本轮会话、观察批次和准备材料存放在 Git 忽略的 `data/runs/`，用于合并前恢复。新流程的当前快照必须包含持续使用所需的分析和证据，不靠历史会话证明其有效性。
历史 manifest 只用于首次迁移或可选审计；当前生成器、校验和新轮次均只依赖正式快照。记录完成时仍验证本轮检查点，合并后不需要 runs。

## 发布输入、META 与统计字段

- 发布输入只组织已有成果，不成为研究事实或结论的替代真相源；推荐对象必须为已完成项。
  `metadata` 以稳定插件 ID 关联快照，仓库数字 ID 和名称必须匹配；`history` 兼容旧输入。
  现有可选 `catalog` 与 `history` 字段仅兼容旧输入，不作为新流程的历史依赖；首次 added 仅表示本工程入档，不代表 npm 发布。
- 发布输入 `summaries` 按插件 ID 绑定作者功能材料的归纳文本、来源 URL 和固定版本；它不是独立验证结论，也不冒充逐字引文。
- 发布输入 `capabilities` 绑定固定版本的人工确认能力条目；省略项不表示已确认数量为零。
- 发布输入 `advice` 是按插件 ID 保存的读者版使用建议；`revision` 必须与研究提交一致，`text` 只润色表达，不改变证据事实或当前结论。
- META 的 `captured_at` 是采集时间，`pushed_at` 是仓库推送时间，两者不能混用。
  缺失／失败值为 null 并保留错误，不用 0 代替未知；GitHub 与 npm 各自时间及窗口独立保留。
- 可选 `npm` 绑定已核实的 `package_name`、下载量、窗口、来源与错误；缺少该对象不等于下载量为零。
  返回包名、窗口与非负整数下载数须匹配，否则记未知；下载量不等于用户数。
- `npm.publication` 的 first_published_at 来自已核实包的注册表 time.created，表示首次发布；采集时间、来源与错误独立保留。缺失或失败不从入档、Git 或下载量推断。
- 可选 `code_update` 绑定研究基线、当前提交、变更路径和核查时间；`script_changed` 为 true／false／null 三态。
  它表示待重新洞察的脚本变化，独立于 findings 的依赖失效状态，不改写研究深度或完成检查点。
- 工程统计的 `revision`／`component`／`coverage` 界定版本、组件及完整或抽读范围；工具版本、内容摘要与排除项须保留。
  静态能力候选不是正式能力数，`confirmed_count: null` 表示未确认，不能转成 0；统计材料同样不可覆盖检查点已绑定的原件。

## 路径、兼容与清理

- 稳定身份与物理目录分离，路径注册表使改名／移动不改变当前入口；轮次目录只标识本轮工作区。
- 未完成增量的证据、报告和检查点不能静默覆写。需要修正时先解除该项完成状态并重新校验，不能只刷新摘要掩盖内容变化。
- 已合并记录的后续变化通过新增量替换当前状态，旧状态可由 Git 查询；不要求重新创建旧轮次或保留所有本地原件。
- 清理前检查当前引用、未合并状态与活动锁；当前仍引用的材料先迁入正式位置并校验，再清理过程副本。
- 旧迁移记录及清理脚本仅适用于其原有归档格式。适配新模型前不得用旧工具扩大删除范围，也不得删除现有材料来绕过校验。更新规范本身不执行数据迁移。
