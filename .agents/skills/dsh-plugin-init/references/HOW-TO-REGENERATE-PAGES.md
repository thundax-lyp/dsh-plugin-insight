# 读者页面重新生成

仅在用户明确要求更新列表编排 Skill 或重新生成读者页面时执行；catalog 内研究原稿、证据与分析版本作为只读输入；不读取旧 runs、manifest 或 checkout，不为排版重做研究或制造新结论。

1. **先更新生成要求。** 将用户确认的阅读目标落实到 Skill 的写作与发布步骤，核对输出标准中的相关约定。已有确认要求优先，不把“改 Skill”替换成直接编辑生成的 Markdown；生成要求与既有标准有冲突时按用户当前要求处理并明确同步范围。
2. **组织三个阅读层次。** 首页顺序为定位、快捷入口、紧凑横幅、推荐尝试、最近发布、下载热门、按场景查找，末尾保留出处、许可与更新时间。推荐最多5项，最近发布与下载热门各最多3项；推荐分行保留用途、推荐理由、试用／安装条件，正文不混排指标；最近发布只突出日期，下载热门只突出下载量。所有徽章复用统一灰色标签与按指标区分的数值色，最新发布为灰标签／绿日期；紧凑表格同色。标题、入口及比较布局统一按[输出标准](OUTPUT-STANDARD.md)实施。
   分类索引先展示分类／任务／数量导航表，再承接每类最多5项的分类 Star 榜；不在README重复展开，不把Star排序称为研究精选。完整分类页保留范围、同类比较表与四标签短评，补齐返回索引／首页及返回比较表入口。
   三个完整栏目先给比较索引，再同序逐项说明；推荐明确试用／安装建议、核查情况和完整使用条件，试用步骤与成本缺少结构化输入时链接完整分析，不编造填充。最近发布新增版本列及研究固定提交，未核实 npm 发版对应关系时提示；下载热门保留下载窗口与研究边界。原有推荐／热度／发版筛选、排序和包去重规则不变，未知指标不填0，不改正式研究原稿或升级验收结论。
3. **应用详情写作要求。** 使用单插件洞察 Skill 的读者组织步骤；顶部用引用块依次给出功能、亮点和主要限制，复用已有摘要和短评并保留证据边界，长篇“插件分析”从“用途与适用场景”开始，再展示能力与流程、效果与成本、工程分析及限制；使用建议放后，核查状态归核查说明，最后保留辅助统计。已有目录时不叠加孤立创新跳转。完整提交链接保留可追溯目标，显示短 SHA；顶部 META 按输出标准展示已核实的“最新发布”日期 Badge；不显示历史对照或“最后更新”徽章，不安排真实宿主验证。
4. **通过生成资源实施。** 检查现有模板与脚本是否支持上述生成要求；需要时修改列表编排 Skill 的生成模板／脚本，而非直接修补 README、分类页或 INSIGHT。已有报告没有逐题材料时不反向编造问题回答或宣称已通过新研究验收。保持数据语义和版本绑定，不从统计、热度或格式推断采用结论；无法安全归类的正文保留原文，不能静默删除或强凑结构。
5. **生成并检查。** 按[成品语言与排版](OUTPUT-STANDARD.md#成品语言与排版)先回读实际生成页面的上下文，检查日常用词、重复标签、术语解释、完整句预览及表格行连续性；不以模板文本检查代替成品检查。执行 `npm run render:research`，回读首页、三栏列表页、分类页及长短详情代表样例；核对主标题“已研究”Badge 的数量、分类索引链接及分类导航、Star 榜和分类索引的固定顺序；检查章节顺序、标题层级、锚点与返回链接、表格宽度、既有证据和假设状态。执行 `npm run check`。生成不代表安装、运行或宿主验收通过；只报告实际结果，未经授权不提交或推送。
