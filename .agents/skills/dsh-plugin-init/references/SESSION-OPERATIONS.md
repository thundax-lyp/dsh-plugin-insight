# 会话与入档恢复

数据状态语义见[研究数据契约](../../_shared/references/DATA-CONTRACT.md#研究会话与脚本检查点)，
正常执行命令见[列表编排 Skill](../SKILL.md)。本页仅处理写入计划、锁与中断恢复。

## 计划与并发

先检查 plan 的语义变化、错误和文件差异，再 apply。基础档案变化、计划损坏或结果非法时，
读取最新档案重新生成计划，不能覆盖并发修改；计划是数据，不作为脚本执行。
原子写入的临时文件须与目标位于同一文件系统。

锁正常释放后才能进入下一次写入。发现已有锁先停止写入；怀疑进程崩溃时，
核对锁内 PID、时间及实际进程，确认无活跃写入者后才人工清理，再重新生成计划。
会话锁按相同方式处理，不自动抢锁。

## 中断后恢复

- apply 成功但 checkpoint 未保存：核对 catalog.runs、批次内容与当前档案，校验后补 checkpoint，不重复 apply。
- 尚未 apply：以最新档案重新计划并检查，再应用和保存检查点。
- 完成材料摘要不符：停止复用，核对原件；修订以新材料、新一轮处理，不覆盖已绑定文件。
- blocked：保留错误、原始材料和部分分析，解决原因后 retry；没有可处理项但仍有 blocked，不算完成。
- 多人共享队列：先外部协调所有权，next 只读，不会认领任务。

## 数据目录迁移

迁移入口为 `npm run migrate:data`，默认只检查计划，明确执行时加 `-- --apply`；完成后 `-- --verify` 核对原件。
现有迁移保留三轮的内部 ID、状态、所选条目与研究结论，只重定位文件和相对引用。
需要修改的记录与报告先在本地逐字节保存原件；MIGRATION.json 记录原始／迁移摘要和新旧路径。
观察／报告内容因路径重定位发生变化时，显式重算检查点摘要及 previous_digest 关联，不将它记作重新研究。
校验会话与历史原件后再使用新目录；不得用新摘要掩盖原件丢失。后续正常研究继续禁止覆盖检查点材料。

## 轮次保留与清理

本地轮次目录用 `YYYY-MM-DD-NN`，会话文件固定为 `SESSION.json`；start 校验输出路径，续跑不改目录。
依据[输出标准](OUTPUT-STANDARD.md#本地-runs-与-git-清单)保留研究证据和断点；`data/runs/` 不进入 Git。
完成或阶段交付后运行 `npm run research -- manifest --session data/runs/<round>/SESSION.json --out data/manifests/<round>.json`，
把来源版本、选择范围、检查点摘要和复现命令导出到 Git 清单。清单不能替代本地原件恢复中断。
运行 `npm run maintain:runs` 先查看计划，再使用 `-- --apply` 清除已审计的重复视图；`-- --check` 验证清理清单及归档原件。
该命令不删研究快照、观察、原稿、断点或锁文件，也不按年龄删除 META。
