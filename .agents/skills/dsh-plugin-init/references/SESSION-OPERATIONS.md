# 会话与入档恢复

数据状态语义见[研究数据契约](../../_shared/references/DATA-CONTRACT.md#研究会话与脚本检查点)，
正常执行命令见[列表编排 Skill](../SKILL.md)。本页仅处理写入计划、锁与中断恢复。

## 计划与并发

先检查 plan 的语义变化、错误和文件差异，再 apply。基础档案变化、计划损坏或结果非法时，
读取最新档案重新生成计划，不能覆盖并发修改；计划是数据，不作为脚本执行。
原子写入的临时文件须与目标位于同一文件系统。

锁正常释放后才能进入下一次写入。发现已有锁先停止写入；怀疑进程崩溃时，
核对锁内 PID、时间及实际进程，确认无活跃写入者后才人工清理，再重新生成计划。
会话锁按相同方式处理，不自动抢锁。

## 中断后恢复

- apply 成功但 checkpoint 未保存：核对 catalog.runs、批次内容与当前档案，校验后补 checkpoint，不重复 apply。
- 尚未 apply：以最新档案重新计划并检查，再应用和保存检查点。
- 完成材料摘要不符：停止复用，核对原件；修订以新材料、新一轮处理，不覆盖已绑定文件。
- blocked：保留错误、原始材料和部分分析，解决原因后 retry；没有可处理项但仍有 blocked，不算完成。
- 多人共享队列：先外部协调所有权，next 只读，不会认领任务。
