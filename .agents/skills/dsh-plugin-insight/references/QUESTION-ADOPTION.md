# 采用判断

研究问题：对什么人值得观察、试用或持续采用，为什么？

本题先完成独立论证，再参与综合 INSIGHT；共同证据要求见[研究规范](RESEARCH-STANDARD.md)。

## 核查方法

综合场景、相对优势、证据强度及全部采用负担，回指相关研究问题及其中的反证和未知项。严重缺陷、效果未知和恢复负担必须影响采用判断，不以综合摘要掩盖冲突。

## 回答要求

明确适合和不适合的人群、必要条件、试用路径、成功及停止标准；按[评分标准](SCORING-STANDARD.md#采用推荐评分adoption-v1)另行保存采用结论与评分，不能按总分自动升级推荐，也不能把源码检查写成宿主验收。

## 从已有回答推导评分

复用现有问题，不为四项评分重新生成一套问卷。按[评分标准](SCORING-STANDARD.md#从已有问题回答到分数)将相关回答映射到scenario、advantage、evidence、cost；每项rationale保留问题链接、回答与具体证据、反证／未知项、档位判据及相邻档取舍。先论证再取档，最后求和；不可用“需求明确／源码可查／接入较轻”替代推导。既有回答不足时明确缺口，不将本次推荐复核表述为新研究或运行验证。

## 最值得推荐的具体用法

采用综合最后只增加一个简明交付：用三句自然完整的话写入现有recommendation.reason（仍为单行字符串），不增加维度、题数、权重或Schema字段。

1. **谁可以用它做什么**：明确人群、已有前提和一项具体任务；工具、客户端、基础设施按真实类型说明，不统称可安装DSH插件。观察／不推荐也说明评估对象，不借缩小任务掩盖核心功能不成立。
2. **比原办法省哪一步或多做成什么**：点明原办法及可由材料支持的增量；仅分析推断时明说，不能把未测节时、成功率或费用写成收益事实。
3. **何时停止或退回原办法**：给出本任务中用户能识别的具体停止条件和可行退路，不能只写“注意风险”“人工复核”。

三句都写成有明确主语和动作的自然中文；首句单独阅读也能说明适用人群及具体任务，供列表预览，不能依靠后句补回关键前提。技术模式、命令和状态首次出现时先解释用途及限制，不写“可试用builtin／先audit／PASS即成功”等省略表达。风险和退路写成用户能识别的现象与动作，不用名词或斜杠串联。

三句来自已有问题回答及固定材料，不另起通用问卷。任一句缺乏依据，先补查最影响采用的具体材料；仍说不清时不强行列为试用／安装，解释观察、未评估或不推荐的原因。四项分数按评分标准独立推导，不从三句文字长度、关键词或热度自动生成。

父Agent验收时逐句问：读者能否决定自己是否适用、是否比原办法值得、何时应退出；能追溯不代表真实收益已验证。推荐复核先形成具体用法和四项依据再查看旧分，不为拉开差距改分；已有材料中的旧判断仅作为待核对线索，不作为本次分数依据。
