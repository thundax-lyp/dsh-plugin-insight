# 功能与机制

研究问题：能力如何从入口、注册、调用、数据流和状态变化中实现？共同证据边界见[研究规范](RESEARCH-STANDARD.md)。

## 核查方法

选择最影响本项贡献或采用判断的实际链路，按以下顺序核对，而不是罗列所有接口：

1. 从用户动作或宿主事件找到真实入口、注册与配置；确认调用方确实使用了所研究机制。
2. 跟踪参数、作用域与外部依赖，直到状态变更、持久化或用户可见结果；区分本组件实现、上游能力和未检查服务。
3. 检查会改变该主张的失败分支。按实际设计区分成功、部分完成、失败和结果未知；取消／超时发生后，核对哪些副作用已发生、哪些状态仍不能确认。

对每条关键判断保留固定文件、行号及原文，说明材料支持哪一步。配置声明、类型定义、函数名和成功消息不能独立证明实际接线或最终结果；不必为无关的潜在风险扩成全仓审计。静态能力候选的确认方法见[工程方法](QUESTION-ENGINEERING.md)。

## 回答要求

解释输入如何成为结果、贡献由哪一步产生、什么条件或失败会改变结论。分别写清作者声称、源码可见和运行未知。动态注册、外部服务或关键实现未覆盖时，明确缺口及其对采用判断的影响，不以“未运行”掩盖可继续核查的关键源码。
